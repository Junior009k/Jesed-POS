REGLAS DE VERSIONADOS


1- El proyecto utiliza el esquema de versionado Semantic Versioning (SemVer), compuesto por tres componentes:

MAJOR.MINOR.PATCH - Ejemplo: 2.3.4

MAJOR (2) - Cambio mayor: Modificaciones importantes que pueden afectar la compatibilidad o el funcionamiento general del sistema.

MINOR (3) - Actualización funcional: Incorporación de nuevos módulos, funcionalidades o mejoras compatibles con versiones anteriores.

PATCH (4) - Corrección: Solución de errores, bugs y ajustes menores sin incorporar nuevas funcionalidades.

2 - Reglas de actualización

Al incrementar MAJOR, MINOR y PATCH se reinician en 0.

Al incrementar MINOR, PATCH se reinicia en 0.

Al incrementar PATCH, únicamente aumenta el último componente.

3 - Objetivo: mantener un control claro y consistente de los cambios realizados en el proyecto, facilitando el seguimiento de versiones, actualizaciones y despliegues.

REGLAS DE NEGOCIOS

IMPLEMENTACION AMBIENTE DE DESARROLLO 

1-Preparar el servidor: Verificar que tenga Windows, conexión a Internet y permisos de administrador.
2-Crear carpeta de trabajo: Crear C:\Aplicaciones para almacenar el proyecto.
3-Descargar el repositorio: Ingresar a Jesed-POS en GitHub, seleccionar Code → Download ZIP.
4-Extraer los archivos: Descomprimir el ZIP y colocar la carpeta del proyecto dentro de C:\Aplicaciones\Jesed-POS.
5-Verificar la instalación: Comprobar que los archivos del proyecto estén disponibles y consultar el README.md.
6-Instalar Git (opcional): Si se necesitan actualizaciones frecuentes, instalar Git for Windows y utilizar git clone para obtener el repositorio.
7-Instalar Visual Studio Code (opcional): Instalar Visual Studio Code si se necesita editar o administrar el código fuente.

Nota: Descargar o clonar el repositorio no significa que la aplicación esté lista para ejecutarse. Es necesario instalar y configurar las dependencias indicadas por el proyecto.
